# Codex 怎么用？先把第一件小任务跑起来

作者：路飞AI · 核对日期：2026-10-13 · [返回教程首页](../README.md)

你不需要一开始就懂模型参数。先让 Codex 完成一个小任务，再看结果，比研究一堆“最佳配置”更有帮助。

## 1. 选一个入口，不必全部安装

可以根据工作习惯选择桌面客户端、编辑器中的 Codex 或终端 CLI。官方入门页有各入口说明和安装链接。[查看官方入口](https://learn.chatgpt.com/docs/quickstart)

本篇以 CLI 为例，安装时请使用[官方 Codex CLI 页面](https://learn.chatgpt.com/docs/codex/cli)提供的方式。Windows、macOS 与 Linux 的步骤可能不同；不要运行陌生人发来的“一键免验证脚本”。

## 2. 在项目目录打开终端

安装完成后，切换到自己的项目目录，再运行：

```sh
codex
```

第一次启动，按提示选择 **Sign in with ChatGPT** 或适合自己的登录方式。官方 CLI 文档说明了在项目目录启动与登录的流程。[官方 CLI 指南](https://learn.chatgpt.com/docs/codex/cli)

先别急着授权：看一眼工具显示的工作目录是不是你的项目。不要在包含大量私人资料的目录里随便启动任务。

## 3. 第一条需求：先了解项目

可以直接复制下面的中文需求：

```text
先不要修改代码。请解释这个项目是做什么的，列出入口文件、
启动方式和测试方式。如果有不确定的信息，请说明，不要猜。
```

让工具先调查，能帮助你发现自己是否打开了正确目录，也便于后续缩小修改范围。

## 4. 第二条需求：只改一个明确问题

```text
请修复登录按钮在手机屏幕上换行的问题。
只调整相关样式，不改变登录逻辑。
完成后检查电脑和手机端，并告诉我改了哪些文件。
```

一条好需求通常包括三个部分：**要解决什么、哪些不能改、怎样算完成。**

“帮我优化一下”范围太大；“390px 宽度下，按钮文字不要换行”就容易验证。

## 5. 看到修改完成，还要自己验收

新手可以按以下顺序检查：

1. 确认修改文件是否符合预期，有没有碰到配置或数据文件。
2. 跑项目的构建、测试，或打开实际页面验证。
3. 检查原有功能是否仍正常，再决定提交或发布。

涉及真实支付、数据库迁移和删除文件时，先留可恢复的备份，并明确允许操作的范围。不要把“自动完成”理解为“可以不用确认风险”。

## 6. 四个实用习惯

- 每次任务前留一个 Git 检查点，方便比较和回退。
- 大改动分阶段：先调查，再改动，最后验收。
- 提供具体报错和相关文件，不把整个硬盘当上下文。
- 项目规则里写验收要求，不写密码、Token 或卡密。

如果任务停住了，先看是否等待你的确认，或者真的触发用量限制，再读[额度专题](04-codex-credits.md)。
